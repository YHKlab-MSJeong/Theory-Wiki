# 개인 이론 위키

연구와 학습에 필요한 개념, 식, 계산 해석을 다시 찾아볼 수 있도록 정리한다.
Markdown으로 작성하고 MkDocs로 사이트를 만든다. [위키 보기](https://yhklab-msjeong.github.io/Theory-Wiki/)

## 문서

[Landauer 수송과 transmission](docs/quantum-transport/landauer-transmission.md) — 확인 중. 새 문서는 [문서 템플릿](template.md)을 참고한다.

## 작성 원칙

- 한 문서에 하나의 질문이나 개념을 다룬다. 필요한 선행 개념은 별도 문서로 연결한다.
- 핵심 식에는 기호, 단위, 부호와 기준, 가정과 적용 범위를 적는다.
- 교과서·논문·공식 문서의 근거와 직접 해석한 내용을 구분한다. 확인하지 못한 내용은 미확인으로 표시한다.
- 계산 경험은 조건과 관찰을 남기고, 일반 이론이나 검증된 결과처럼 단정하지 않는다.
- 초안은 짧아도 된다. 검증이 끝나지 않은 초안은 확인 완료 문서와 구분한다.

## 과학적 검증 기준

- 자명하지 않은 과학적 주장마다 독립적인 출처 두 개 이상을 직접 확인하고, 각각의 절·페이지·식 등 근거 위치를 기록한다. 단순한 복제나 같은 출처를 인용한 자료를 독립 근거로 세지 않는다.
- 핵심 식은 기호와 단위, 부호·좌표·정규화 관례, 가정, 근사 수준과 적용 범위를 확인하고 물리적 의미를 설명한다. 유도한 식이나 예제는 근거가 되는 전제와 재현 가능한 유도 과정을 남긴다.
- 출처가 서로 다른 가정이나 범위를 쓰는지 확인한다. 충돌이 해결되지 않으면 차이를 기록하고 확인 완료로 표시하지 않는다.
- 확인 불가능한 출처나 미검증 주장은 추측하여 채우지 않는다. 원문에 접근하지 못했거나 근거가 부족하면 미확인으로 남긴다.
- 새 문서의 전체 주장, 변경된 문서의 변경 주장과 영향을 받는 결론을 검토한다. 가능하면 작성과 독립된 검토자가 원문 대조를 수행한다.
- 링크 점검이나 형식 검사는 과학적 정확성 검증을 대신하지 않는다. 공개 여부와 관계없이 문서 상태는 근거 확인 결과에 따라 표시한다.

## 작성 순서

1. 질문과 적용 범위를 정하고 원문 근거를 수집한다.
2. 식의 정의와 가정을 명시하고 필요한 유도를 한글로 작성한다. 주장과 출처의 대응을 기록한다.
3. 독립적인 관점에서 원문, 식, 부호, 근사와 미확인 사항을 검토한다. 검토가 끝나기 전에는 `확인 중`으로 둔다.
4. humanizer 스킬로 표현을 다듬고 수식·조건·출처·주장의 강도를 편집 전과 대조한다. 문체 교정은 사실 검증을 대신하지 않는다.

로컬 미리보기는 `python -m pip install -r requirements.txt` 후 `mkdocs serve`로 실행한다. `mkdocs build --strict`는 사이트 형식 검증이다.

구성과 작성 원칙은 [RGLee-Wiki](https://github.com/ryonggyulee/RGLee-Wiki)를 참고하여 개인 학습용으로 새로 정리했다.
